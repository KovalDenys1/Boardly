# Android TWA Implementation Plan (#1467)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A signed Android App Bundle that opens boardly.online full screen as a Trusted Web Activity, ready for a Google Play closed test.

**Architecture:**
- **Generated, not hand-written.** The Android project is generated by Bubblewrap 1.27.0 from `android/twa-manifest.json` and committed under `android/`. The `.gitignore` keeps build outputs and keys out.
- **Upload key.** It lives outside the repo, and its password is in the macOS login keychain. `npm run android:build` reads the password from the keychain and runs `bubblewrap build` without prompts.
- **Asset links.** `public/.well-known/assetlinks.json` ties the origin to the package. The proxy already skips `.well-known/` (`proxy.ts` matcher).

**Tech Stack:**
- Bubblewrap CLI 1.27.0 (`npm i -g`), installed at `/opt/homebrew/lib/node_modules/@bubblewrap/cli`.
- JDK 17 at `/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk`.
- Android SDK at `/opt/homebrew/share/android-commandlinetools`, with platform 36 and build-tools 36.0.0 installed.
- `~/.bubblewrap/config.json` is already set, and `bubblewrap doctor` reports valid paths.

**Spec:** GitHub issue #1467. Research and sources are in the vault note `03 Projects/Boardly/Android Play Research 2026-10-18.md`.

## Global Constraints

- **Identity:** `packageId` `online.boardly.app`; `host` `boardly.online` (apex only, because www answers 301); `name` "Boardly" (the Android app label; the Play listing title is #1468's); `launcherName` "Boardly".
- **Launch:** `startUrl` `/?utm_source=android_app&utm_medium=twa`, exactly the pair #1465 detects.
- **Display:** `display` `standalone`; `orientation` `portrait`; `themeColor` `#1F1B16`; `navigationColor` `#1F1B16`; `backgroundColor` `#FBF6EE`.
- **Behaviour:** `enableNotifications` `true`; `fallbackType` `customtabs`, because a WebView fallback breaks Google sign-in.
- **SDK and versions:** `minSdkVersion` `24` (android-browser-helper 2.7.4 needs it); `appVersionName` `1.0.0`; `appVersionCode` `1`.
- **Icons:** `iconUrl` `https://boardly.online/icons/icon-512.png?v=3`; `maskableIconUrl` `https://boardly.online/icons/icon-maskable-512.png?v=3`.
- **Shortcuts:** the two from `public/manifest.json`.
- **Signing key:**
  - keystore `~/.config/boardly-android/upload-key.jks`, alias `upload`, RSA 2048, validity 10000 days, dname `CN=Boardly, O=Boardly, C=NO`;
  - keystore password = key password = 32 random characters, stored with `security add-generic-password -a boardly -s boardly-android-upload -w`;
  - **never print the password, never write it to a file, never commit the keystore.**
  - Keep a copy of the keystore at `~/Library/Mobile Documents/com~apple~CloudDocs/Keys/boardly-upload-key.jks`.
- **Web manifest:** `public/manifest.json` gains `"id": "/"`.
- **Heavy commands:** `nice -n 10` on every gradle or bubblewrap build. The machine has 16 GB and other agents run alongside.

## Review Focus

1. **Wrong asset-links fingerprint.** The app then opens with a URL bar. A test checks the JSON's shape, package and fingerprint format, and the release steps in `docs/ANDROID.md` name the second fingerprint (the Play app-signing key) that must be added after the first upload (Task 2).
2. **A rebuild reverts hand edits.** `bubblewrap update` regenerates the project from the manifest, so every setting must live in `twa-manifest.json`, never only in the generated Gradle files (Task 1: regenerate, then `git diff` is empty).
3. **The keystore password leaks** into shell history, logs or a committed file. The build script reads it from the keychain into the environment of the one child process (Task 2 grep check).
4. **Phones with gesture or 3-button navigation on Android 16** draw edge to edge, so the bottom game tabs could sit under the navigation bar. Check on the emulator in Task 3. The site already uses `env(safe-area-inset-*)` and `viewportFit: cover`.
5. **An invite link opened from another app** must open in the TWA in Play mode, or at least not show a purchase path (Task 3, on the emulator).

### Task 2: Signing, the build script and asset links

**Files:**
- Create: `scripts/android-build.sh`, run with bash and `set -euo pipefail`. It:
  - reads the password with `security find-generic-password -a boardly -s boardly-android-upload -w`;
  - exports it as `BUBBLEWRAP_KEYSTORE_PASSWORD` and `BUBBLEWRAP_KEY_PASSWORD` for one `nice -n 10 bubblewrap build --skipPwaValidation` run inside `android/`;
  - prints the paths of `app-release-bundle.aab` and `app-release-signed.apk`;
  - exits non-zero with a one-line hint when the keychain item or the keystore is missing.
- Modify: `package.json`, adding the script `"android:build": "bash scripts/android-build.sh"`.
- Create: `public/.well-known/assetlinks.json`, in the shape from Global Constraints, holding the upload key's SHA-256 fingerprint (uppercase hex pairs joined by `:`).
- Test: `__tests__/public/assetlinks.test.ts`. It reads the file and asserts:
  - it is an array with one statement;
  - `relation` equals `["delegate_permission/common.handle_all_urls"]`;
  - `target.namespace` is `android_app`;
  - `target.package_name` is `online.boardly.app`;
  - every fingerprint matches `/^([0-9A-F]{2}:){31}[0-9A-F]{2}$/`;
  - there is at least one fingerprint and the list has no duplicates;
  - `android/twa-manifest.json`'s `packageId` equals the asset-links package.

- [ ] **Step 1: Generate the key.** If `~/.config/boardly-android/upload-key.jks` already exists, stop and report: never overwrite a key. Otherwise:
  - generate the password with `openssl rand -base64 48 | tr -dc 'A-Za-z0-9' | head -c 32` into a shell variable;
  - store it with `security add-generic-password -a boardly -s boardly-android-upload -w "$P"`;
  - create the key with `keytool -genkeypair` (the JDK 17 `keytool`), passing `-storepass:env` / `-keypass:env` so the password never appears in the process list;
  - `chmod 600` the keystore and copy it to the iCloud backup path.
- [ ] **Step 2: Write the failing asset-links test.** Run `nice -n 10 npx jest __tests__/public/assetlinks.test.ts`. Expected: FAIL, because the file is missing.
- [ ] **Step 3: Write `assetlinks.json`** with the fingerprint from `bubblewrap fingerprint generateAssetLinks`, or from `keytool -list -v`, reading the password from the keychain.
- [ ] **Step 4: Run the test.** Expected: PASS.
- [ ] **Step 5: Run the build:**
  - `npm run android:build`: both artifacts exist;
  - `keytool -printcert -jarfile android/app-release-signed.apk` shows the same SHA-256 as `assetlinks.json`;
  - `unzip -l android/app-release-signed.apk | grep -c "^.*lib/"` is 0, so there is no native code and the 16 KB page rule is met.
- [ ] **Step 6: Check for leaks.** `git grep -n -i "storepass\|keypass\|BUBBLEWRAP_KEY" -- . ':!scripts/android-build.sh' ':!docs/ANDROID.md'` finds nothing, and `git status` shows no `.jks`, `.aab` or `.apk` files.
- [ ] **Step 7: Commit** with `#1467 feat: upload key, build script and Digital Asset Links`.

### Task 3: Emulator verification (after `assetlinks.json` and #1465 are live on boardly.online)

**Files:** no code changes. Results and screenshots go into the report file and a PR comment.

- [ ] **Step 1: Install the emulator.** Run `sdkmanager "emulator" "system-images;android-36;google_apis_playstore;arm64-v8a"`, then create the AVD with `avdmanager create avd -n boardly-36 -k "system-images;android-36;google_apis_playstore;arm64-v8a" -d pixel_8`.
- [ ] **Step 2: Boot it** with `emulator -avd boardly-36 -no-window -no-audio -no-snapshot -memory 2048` in the background. Wait with `adb wait-for-device` and then for `getprop sys.boot_completed` = 1. Install with `adb install android/app-release-signed.apk`.
- [ ] **Step 3: Check the asset links.** `curl -sI https://boardly.online/.well-known/assetlinks.json` must give 200 with `content-type: application/json` and no redirect.
- [ ] **Step 4: Launch** with `adb shell monkey -p online.boardly.app 1`, then screenshot with `adb exec-out screencap -p`. Expected:
  - no URL bar;
  - `adb shell dumpsys activity activities | grep -i customtab` does not show a Custom Tab;
  - the page has `data-app-shell="play"`, checked through `chrome://inspect` remote debugging: `adb forward tcp:9222 localabstract:chrome_devtools_remote`, then a CDP `Runtime.evaluate` of `document.documentElement.dataset.appShell`.
- [ ] **Step 5: Walk through the app**, taking a screenshot at each step:
  - open `/premium` from the footer: no buy controls, and the notice is shown;
  - start a bot game in Tic-Tac-Toe and make two moves;
  - the bottom tabs are clear of the navigation bar in both gesture and 3-button mode (`adb shell cmd overlay enable com.android.internal.systemui.navbar.threebutton`);
  - the back gesture leaves the game page as on the web;
  - "Sign in with Google" opens accounts.google.com in a Custom Tab; you need not finish signing in.
- [ ] **Step 6: Open an invite link** with `adb shell am start -a android.intent.action.VIEW -d "https://boardly.online/lobby/TEST"`. It opens in the app, and `data-app-shell` is `play`. If it is not, record the referrer seen and report DONE_WITH_CONCERNS: the deep-link referrer is unverified in the research.
- [ ] **Step 6b: Open the app from other entry points.** In each case, buy controls must be absent:
  - a push notification, with the app closed (`public/sw.js` `openWindow` opens a fresh tab with no parameters and no stored mark);
  - a link from a mail (a password reset);
  - `/profile?tab=premium` signed in with a premium test account and with a free one.

  For any case that shows buy controls, report DONE_WITH_CONCERNS with the referrer and URL seen.
- [ ] **Step 7: Shut down** with `adb emu kill`, and leave the AVD in place for later releases.
